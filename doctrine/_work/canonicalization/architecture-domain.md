# Architecture and Domain Canonicalization Ledger

Status: final-candidate canonicalization for the architecture/domain lane. This ledger canonicalizes only `SRC-CA`, `SRC-FSA`, and `SRC-DDD`; it does not edit or claim authority over final doctrine or graph artifacts.

## Source IDs and evidence rules

- `SRC-CA` = `books/clean-architecture-a-craftsman-guide-to-software-structure-and-design`
- `SRC-FSA` = `books/oreilly-fundamentals-of-software-architecture-2020-1`
- `SRC-DDD` = `books/domain-driven-design-tackling-complexity-in-the-heart-of-software-eric-evans`
- Locator form: `SOURCE: chapters/file.md :: exact converted heading`.
- Provenance relations:
  - `direct_support`: the source explicitly advances substantially the canonical proposition.
  - `corroboration`: the source independently advances a materially similar operational proposition.
  - `refinement`: the source narrows, conditions, decomposes, or adds consequences.
  - `derived_inference`: defensible synthesis, not a proposition directly stated by that source.
  - `tension`: the source formulation limits, conflicts with, or exposes a terminology collision in the candidate.
- Only material formulations are listed. Source silence is not converted into support.
- Repository evidence and accepted project contracts remain runtime constraints above this source-derived ledger.
