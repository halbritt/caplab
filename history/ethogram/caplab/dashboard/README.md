# CAPLAB study-results dashboard

This package renders checked-in study aggregates for local review. It has no
mutation endpoint and does not read CAPLAB evidence stores. The running server
loads application files and JSON projections from this directory at startup;
it never invokes Git or writes a file while serving requests.

Study 001 is a historical Git projection. It is not P6 evidence admission or
P7 CAPLAB recomputation. ADR 0006 selected the exact capability-card artifact;
capability inference, technical verification, and CAPLAB acceptance remain
unavailable.

The page starts with a study-specific plain-language overview: why the study
exists, why CAPLAB selected it, the checkout scenario, the preregistered
question and hypothesis, the B/V treatment difference, the primary outcome,
the harness/model/effort subject tuple, the fixed design, the historical
result, its bounded interpretation, and a glossary. Raw aggregates, methods,
provenance, status, and the capability card follow that overview.

## Project Study 001

The projector resolves three fixed Git objects, checks their complete SHA-256
identities, validates the exact 30-column and 20-row CSV contract, and
recomputes every rendered aggregate. It also enumerates all 256 within-block
sign assignments for the preregistered one-sided exact test. A source, schema,
row, outcome, or aggregate mismatch raises `ProjectionError`; no partial JSON
is written.

Generate the checked-in projection from the card committed under
`docs/product/capability-cards/`:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m caplab.dashboard.projector \
  --repo-root . \
  --output caplab/dashboard/studies/caplab-study-001.json
```

Replace the command's final action with `--check` to compare regenerated bytes
with the checked-in file:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m caplab.dashboard.projector \
  --repo-root . \
  --output caplab/dashboard/studies/caplab-study-001.json \
  --check
```

The committed file preserves the exact proposal bytes and therefore retains
`status: proposed`. ADR 0006 is the separate authority for the current
`selected` disposition. The generated projection contains both states plus the
hash-verified construct, scope, exclusions, rivals, and promotion gates. A
missing or changed artifact makes the preview unavailable without rewriting
ADR 0006's decision.

## View-model contract

`study-results-dashboard/3` is deterministic UTF-8 JSON with sorted keys,
two-space indentation, and one trailing newline. Each file name equals its
`study_id`. The server requires these top-level fields:

- study identity: `study_id`, `display_id`, `title`, and `catalog_summary`;
- reviewer orientation: `study_context`, including the scenario, selection
  rationale, question, hypothesis, arm definitions, primary-outcome
  definition, required harness/model/effort subject tuple, design,
  plain-language result, interpretation, metric explanations, reading guide,
  and unique glossary terms;
- status: `claims`, with state kind, source scope, and status kept apart;
- observations: `primary`, `secondary`, `clean_sentinels`, `paired_blocks`,
  and typed `trials`;
- review context: `missingness`, `provenance`, `methods`, `claim_boundary`, and
  `capability_card`.

JSON booleans remain booleans. Unavailable trial fields are JSON `null`, not
zero or an empty string. Mutant concurrency fields are unavailable; clean
sentinels retain 40 successes and 10 bad orders. Token fields are reported
individually and are not added together.

The renderer keeps the overview expanded and the glossary collapsed by
default. It shows the overview and primary result before the full status
ledger, so a first-time reviewer does not need CAPLAB stage names to understand
the study question or result.

The catalog scans `studies/*.json` in lexical order. A new conforming projection
appears in `/api/studies` and uses the same UI renderer. Invalid files remain in
the catalog as unavailable, and their study endpoint returns `503` without
returning stale bytes.

## Run locally

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m caplab.dashboard.server \
  --bind 127.0.0.1 \
  --port 3021
```

The service refuses non-loopback bind addresses. Its routes are:

- `/`, `/app.css`, and `/app.js`;
- `/api/studies` and `/api/studies/<study-id>`; and
- `/healthz`.

`GET` and `HEAD` are the only accepted methods. Mutation methods return `405`
with `Allow: GET, HEAD`. Every response disables caching and indexing, refuses
content-type sniffing and referrers, and uses a same-origin Content Security
Policy with no third-party resources.

Run the focused tests with:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest -v tests.test_caplab_dashboard
```
