## Design and preservation review

Leaving the diagnostic private would preserve the demonstrated integration but
retain manual source substitutions and no reusable attempt lifecycle. Extending
the existing startup probe would combine its offline-error controls with a
different scripted-exchange contract. Select a separate three-operation caller
and share the established public readers and capture helpers. The helper
package groups lifecycle, supervisor, capsule, wire fixture and inspection
responsibilities without a general backend abstraction. Capsule files are
separate because they are explicitly mounted into the isolated filesystem.

The structural derivation preserves the fixed payload, handshake ordering,
limits, quarantine and known transport-error classification. The authorized
semantic changes are prospective preparation and source validation, durable
single-consumption ownership, explicit failed-result publication and separate
inspection status. Existing runtime modules and startup producer stay unchanged.
No independent annotations/checker migration or general performance claim is
made. The tests cover malformed preparation, concurrent consumption, partial
custody, protocol ordering/deadlines and real freeze/thaw failures; the native
integration tests the actual CLI and process dependencies. This is bounded
protection of the stated interface, not an exhaustive security or failure audit.
