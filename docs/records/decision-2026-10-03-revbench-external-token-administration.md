# Additive Revbench external-token administration

## Authority and scope

Root252 selects this prospective administration under active ADR 0026 and the
owner's shared subscription backend implementation mandate. This explicitly
reopens ADR 0063 for one additive credential method. It authorizes source
implementation, synthetic tests, documentation and an isolated review branch
from `b0673b6c0cb95dfcac70e5f5094b505e1dc2e7ca`. Implementation belongs to Caplab.
The destination remains shared catalog and account admission across all four
consumers; this native adapter enables one consumer prerequisite.

This decision grants no live administration. Actual registration, apparatus
preparation, custody use, private provisioning, refresh and provider effects
remain a later exact, registered, time-bounded execution decision. No historical
evidence effect is authorized. Independent GPT-6.1 Sol review is required before
root accepts and integrates Sonnet's implementation.

## Selected contract

1. Add a closed, explicitly named external-token Revbench credential profile
   and separate bundle-policy identity. Preserve existing v1 policy bytes,
   profile behavior, external API default and historical bindings. A material
   administration change produces new runtime, command and Binding identities.
   Do not silently select the new method for an existing profile or accept a
   mismatched method/profile/policy combination.
2. Reuse `open_codex_external_credential` version 1 delivery with explicitly
   selected `credential-private-text/v2` quarantine policy. Its existing
   location/type-sensitive category rules govern only the new profile. The
   delivered document uses `chatgptAuthTokens`, keeps the refresh-token key with
   an empty value, and preserves other token strings. Pin initial native
   credential-store configuration to `file`, so the sealed read-only auth file
   is loaded. Do not use initial `ephemeral` storage, a host keyring or a host
   config fallback. No external refresh provider or hook is added.
3. Preserve Codex 0.147.0, GPT-5.6 Terra, maximum effort, configured direct
   OpenAI route, existing subject tools/network boundary, exact native members,
   read-only sealed delivery, isolated source entrypoint and custody domain.
   Additive profile/bundle selection must agree in preparation, execution,
   launch plans and later evidence revalidation. Qualification remains advisory
   for configured routes; no automatic qualification transfer or upgrade.
4. Keep source SHA256 and expected account/subject SHA256 anchors exclusively
   in separately supplied private administration context, bound to the selected
   public profile identifier. Do not derive expected identities from the file
   being validated and treat that as independent checking. The public profile
   identifies method, marker policy and deadline rule without private source
   paths, token metadata, whole-cache hashes or raw private claims. Existing v1
   public profiles retain their old semantics. Private input must be closed,
   owned and permission-checked, with fixed-code refusals and no raw serialization
   into command lines, errors or evidence. Reuse the current private runtime
   provisioning owner; extend its supported API/CLI deliberately if necessary.
5. The access token must cover the entire effective execution deadline, including
   version probes and administration overhead. Derive required lifetime with
   upward rounding from a fresh trusted UTC reading to that retained deadline,
   clamp only the minimum positive requirement to one second, and reject if
   the existing API's 86400-second maximum cannot cover it. Do not truncate a
   longer requirement or extend authorization. Keep existing monotonic process
   and total deadlines; clock movement cannot create extra time. Expired ID
   metadata is permitted only by this explicit external profile. Its remaining
   issuer, audience, issue-time, account/subject and source-stability predicates
   stay intact. Local unsigned checks are not provider authentication.
6. Acquire the lease after the existing durable overall one-shot intent and
   before any version/provider-capable subprocess. Refusal consumes and seals
   the same fresh slot; recovery cannot relaunch after uncertainty. Preserve
   direct-child source selection, mode0700 credential root, source mode0600,
   owner/no-follow/single-link/stability/size checks and custody disjointness.
   Use a context-owned composition adapter exposing the descriptor and fresh
   stream guards without leaking descriptor lifetime or private marker internals.
   Avoid reverse top-level imports that create an initialization cycle.
7. Apply the selected fresh quarantine guard to every durable output stream,
   metadata, failure and mount-description surface carrying credential-derived
   text. Policy must remain transitively pinned and revalidated. Quarantined
   capture is unavailable, never successful empty output. Fixed-code errors
   must not interpolate source paths, claims or exception contents. Preserve
   existing nonrollback one-shot intent/process/assignment rules and evidence
   graph verification; add no second custody ledger or retry mechanism.

## Preservation, verification and stop rules

This is additive semantic implementation, not behavior-preserving refactoring.
Keep scope limited to the credential/profile/bundle/runtime seam and necessary
source packaging and supported CLI changes. No new dependency, tuple, proxy,
provider, host policy or containment topology is selected. Routine closed field
names and internal composition belong to the implementer within these rules;
changes to the selected semantics return to root for a named successor decision.

Synthetic verification must discriminate: old-profile and pinned policy replay;
new-profile/policy/runtime disagreement; exact sealed external projection;
source unchanged and descriptor cleanup; fresh guard state; expired ID only in
new mode; insufficient access lifetime, rounding and deadline refusal; root,
source and private-anchor mismatch; post-intent refusal and no-retry recovery;
launch/evidence substitutions; preservation of private occurrences equal to v2
categories; and no unguarded durable failure or metadata path. Use fake credential
fixtures only. Verify supported preparation and isolated source command shape.
Do not relabel host-bound failure as a successful synthetic result.

Pinned-binary external-mode parsing and actual read-only delivery remain
unverified. The prior offline campaign stopped before Codex at Bubblewrap's
RTM_NEWADDR failure. Host namespace remediation is separately reviewed and
selected; this branch may not alter host AppArmor/sysctl, install a launcher,
substitute host-latest members or rerun those native cases. Native parsing,
real capture usability and authorized administration remain later evidence,
not claims earned from these source tests. Built-in OAuth suppression does not
mean zero HTTP retries or exactly-once provider delivery. Exact-text quarantine
does not provide transformed-secret detection or memory zeroization.

Stop source work only at a concrete semantic conflict with these constraints;
report the smallest unresolved choice while continuing independent work. Do not
weaken old guards, rewrite frozen evidence, remove preserved failed artifacts,
access real credentials or invent a new personal permission gate. Cleanup is
limited to task-owned synthetic temporary data/processes; retain test/review
receipts and the worktree for integration. No time-bounded live effect is granted.
