These are development investigations of ordinary native review output, not
ranking measurements. The reviewer task contains the original Council change,
its first-parent base and original documentation. It supplies no known bug
report, later repair, hidden witness or suspect-location list. The requested
output is actionable findings with a trigger, expected/actual behavior and
causal explanation; executable reproduction is optional.

The sources are Council `de4a6d4d195ea0054e275548d49ef12fb5d13d0e` (47
regular files) and `9c66a76836245fbc8d203812a4a36f475341ce0e` (115 regular

The original introduction is a development lineage follow-up, not a random

## First attempt and local diagnosis

Output-probe-1 exited with status 1. The native stream reported repeated HTTP
401 responses with missing authentication and a missing code-mode helper.
There was no final review or reviewer finding. This is an execution failure,
not a missed defect or a correct clearance. The retained root session reports
Codex CLI 0.153.4, `gpt-5.6-terra`, effort `max`; reported configuration alone
does not establish successful provider execution.

The runner reused the sealed credential descriptor after a version-only
Bubblewrap preflight. A provider-free fixture demonstrated the failure
mechanism: a first consumer received 17 bytes, the second received zero, and
resetting the open descriptor's offset restored 17 bytes. Local native
login-status checks accepted both `chatgptAuthTokens` and `chatgpt` projections
with an empty refresh token. The first pair of status checks had instead
failed argument parsing because `--ignore-user-config` is an exec option;
those failures are also preserved. No status check contacted a provider.

This supports a descriptor-consumption explanation for the missing credential;
it is not evidence that the owner's original authentication cache was invalid.
The installed package also contains a separate `codex-code-mode-host`, which
the first namespace omitted. The second authorization changes those two
preparation details, retaining the external-token projection and original task.

First-attempt custody is
`/home/halbritt/.local/share/caplab/reviewer-ranking-001/development/output-probe-1`.
It preserves the runner, plan, launch, completion, guarded native stdout,
stderr and root rollout, and both status-check records. The exact-secret

## Second attempt and capture validity failure

Output-probe-2 progressed into native review activity, then was killed at its
300-second deadline (303.08 seconds including guarded collection). It created
no final-message file. The retained stderr includes a native tool rejection
for a temporary-directory cleanup command. That is an administration limit,
not evidence about the correctness of the proposed change.

The guard withheld 14 files, including stdout and the root rollout, and
retained 321 files. The main transcript is unavailable, so its reported model
identity, tool/final linkage and findings cannot be verified after capture.
Intermediate live event counts are diagnostic observations, not a substitute
for retained review evidence. Neither a completed review nor a defect catch
is established. The wider runtime capture also includes downloaded plugin
material; it is not yet a fully pinned, comparable administration.

A subsequent provider-free check applied the unchanged guard to all 163 task
files (the two trees and patch). Six were rejected: both original protocol
files, the current protocol, patch, configuration and provider runtime. At
least one credential metadata string also occurs in the authorized source.
This demonstrates that ordinary source quotation can cause capture loss.
It does not establish which bytes triggered the now-unavailable transcript,
or establish that no credential appeared there. The private check records
paths and counts without printing credential metadata values.

The next required correction is to validate capture against legitimate task
content while preserving protection of actual credential material, and retain
safe evidence when an individual record is withheld. That correction needs
adversarial checks before more reviewer calls. A five-minute incomplete review
of this large original change also cannot determine an adequate comparison
budget. No third reviewer launch is authorized by these records.

Both attempts and the task-content guard check are anchored in
`../product/studies/reviewer-ranking-001/output-probes-development-receipt.json`.
The second custody root is the first root with `output-probe-2` as its last
component. No raw source, credential or private native transcript is committed.

## Interpretation boundary

The authorizations permit one outer review launch each, with a 300-second
deadline. Internal native transport retries are inside that limit; neither
authorization is a hard dollar cap. The native subject policy was checked
before preparation. Filesystem isolation excludes owner homes and the hidden
verification trees; provider networking remains available. Tool traces must
be checked before claiming that the subject stayed within the supplied task.

These preparations do not establish scoring accuracy, comparable budgets
across other harnesses, independently verified findings, clean-control
specificity, adequate case coverage or a reviewer ordering. The earlier
provider-lifetime witness establishes behavior on exact source revisions;
attributing that behavior to a reviewer's substantive finding is a separate
step. All new findings must be preserved, including those outside that witness.

Twenty-two focused existing checks passed for native invocation construction,
external-credential handling and event parsing. The first test command lacked
the repository's `PYTHONPATH=src` and failed imports; the corrected commands
passed. No product runtime code changed, and the full suite was not repeated.
Those checks do not validate this failed end-to-end review instrument.
