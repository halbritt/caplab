# Native streaming model evidence, version 1

Status: implemented semantic repair. See the
[decision and verification record](../../records/repair-2026-09-08-native-stream-model-evidence.md).

`caplab.review_dissent.native.assess_native_review_model` checks Claude model
observations in completed messages and exposed partial events. Existing system
initialization, assistant model and system fallback checks remain. The assessor
adds these structured surfaces:

| Native location | Recorded observation | Effect |
|---|---|---|
| `stream_event.event.message` when `event.type` is `message_start` | Model and JSONL line in optional `stream_models` | Every observed model must agree; absent/invalid model prevents agreement. |
| `assistant.message.content` and streamed `content_block_start.content_block` with type `fallback` | Source, line, index, `from.model`, `to.model` in `fallbacks` | Explicit fallback prevents attribution even without model details. |
| `usage.iterations` with type `fallback_message` on completed assistant messages, streamed message start/delta, or terminal result | Source, line, index and fallback model in `fallbacks` | Explicit fallback prevents attribution. |

When present on a streamed `message_start`, content fallback blocks are checked
as well. A streamed content-block index is retained as reported, without a
claim of complete block-order validation. Duplicate observations from completed
and partial surfaces remain separate locators; their count is not a count of
independent fallbacks or model actions.

The optional `stream_errors` list identifies malformed partial envelopes or
content-block starts that cannot support agreement. Missing or malformed
message-start model fields appear as their raw value (or null) in
`stream_models`. These fields extend the existing
`caplab.review-dissent.native-model-identity/v1` observation without changing
ordinary non-streaming result fields. Existing capture/observation versions
remain unchanged; historical records are not regenerated by this repair.

Explicit off-pin models and fallback markers produce `model-mismatch` even when
other evidence is missing. Missing evidence produces `model-unverified`.
Matching partial fields never replace the required completed assistant response,
single initial record and successful final result. The assessor checks selected
identity fields, not full partial-message sequencing, tool completion, session
linkage, source provenance or native capture completeness.

The existing scoring and continuation gates consume these statuses: withhold
mechanical credit, preserve execution status and assigned slots, and refuse
next-attempt preparation after missing or mismatched identity evidence.
Aggregate `modelUsage` keys remain advisory. Arbitrary tool inputs, text deltas,
quoted fallback examples and unknown well-formed partial types are not searched
recursively for model names or fallback claims.

Claude documents the `stream_event` wrapper and raw event field in its
[streaming output reference](https://code.claude.com/docs/en/agent-sdk/streaming-output).
The [Messages streaming reference](https://platform.claude.com/docs/en/build-with-claude/streaming)
places model identity on `message_start.message`. Its
[fallback reference](https://platform.claude.com/docs/en/build-with-claude/refusals-and-fallback)
describes explicit fallback blocks and `fallback_message` usage iterations,
including final streamed usage. These documents establish the inspected field
formats; synthetic fixtures establish parser behavior. No claim is made that a
particular installed CLI/account currently emits every surface. No SDK or proxy
is introduced, no capture option changes, and no native/model invocation occurs.
