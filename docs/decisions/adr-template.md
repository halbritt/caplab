# Decision title

Status interpretation: this record is a draft. It contains no architectural
selection and grants no implementation authority.

## Decision question and scope

State one architectural question and the repository, product, context, or
interface boundary it governs. Name adjacent questions that remain out of
scope.

## Observations and evidence

Record inspectable facts with paths, revisions, commands, incidents, or typed
evidence records. Do not place explanations or preferences here.

## Inferences, rivals, assumptions, and uncertainty

Explain what the observations may mean, credible rival explanations, material
assumptions, and evidence that would change the analysis.

## Recommendation and alternatives

State the preferred option, alternatives including no change, costs, risks,
reversibility, and the conditions favoring each option.

## Decision, owner, authority, and rationale

Leave unresolved while the ADR is `draft` or `proposed`. When an owner selects
an option, state the selection, owner, authority source, rationale, scope, and
decision date.

## Authorization and execution scope

Record implementation authorization separately from the decision. Name the
authorized paths, systems, semantic changes, stop conditions, and expiration or
reconfirmation rule. Leave unresolved when execution is not authorized.

## Consequences and preservation boundaries

Record gained capabilities, costs, compatibility constraints, migration or
maintenance obligations, and behavior or data that must remain unchanged.

## Verification and fitness criteria

State checks capable of showing whether execution conforms to the decision.
Separate deterministic checks, runtime evidence, human adjudication, and final
acceptance.

## Acceptance owner and outcome

Name who can accept the verified result. Record the outcome only after that
owner judges it sufficient.

## Reopening and supersession conditions

Name evidence, changed assumptions, costs, incidents, or context changes that
would reopen the decision. Link the replacing ADR reciprocally when
superseded.

## Related artifacts

Link specifications, plans, receipts, implementation changes, verification,
and acceptance records without treating one artifact as another.
