# Native calibration shared admission

Select additive opt-in admission for future authorized preference and
review-dissent native campaigns. The existing manifest, source pins, native
agent-system instrument, task-only containment, trial order, replacement rules,
expiry, output and observation contracts remain governing. This decision does
not reopen an expired campaign, change a subject, or admit historical evidence.

Each subject version/auth helper, the containment version helper, and each
native trial receives a separate one-shot assignment in the existing campaign
custody root. Explicit pinned operator mappings cover both subjects and the
platform helper; they may conservatively share a finite account domain. They
are local declarations, not provider authentication. All mappings must select
one SDK home and policy. Quartermaster alone owns numeric resource accounting.

Use the established SDK interval/reconciliation protocol and owned PID1
readiness mechanism before release. The native command remains unchanged
after a pinned in-sandbox explicit-byte exec gate; EOF cannot release it.
Positive outer creation counts once, including later exec failure; a Popen
exception retains uncertainty. Genuine pre-Popen refusal can retire an unused
closed right. A constructor exception cannot. Preserve immutable possible
creation evidence, actual same-boot clock brackets and genuine namespace
closure. Recovery verifies retained intent/output/completion and never creates
another child. Missing native outcome or closure stays held.

Authorize isolated source changes, provider-free private SDK/local-process
controls, documentation, and a source-pinned wheel. A separately recorded
tested-commit integration selection precedes installed adoption. Preserve
active campaigns, credentials, historical custody, current unenrolled behavior,
and existing retrieval/pool interfaces. No production admission-home writes,
provider/model calls, historical campaign continuation, scientific qualification
or measurement acceptance is selected here. Stop and retain unexpected setup,
creation, accounting, custody or provenance results; correct demonstrated
defects without weakening controls. Other producers remain explicit residuals.

The focused preservation run exposed an existing identical-enrollment
publication race in the common shared-sidecar retention helper. Select the
narrow idempotence repair: after an authentic atomic-link FileExists race,
read, validate and directory-sync the winner through existing custody code.
Accept it only when its complete canonical preimage equals the requested one.
Conflicts, malformed ownership, symlinks and other publication errors still
refuse. No generic custody writer, resource transaction or schema is changed.
